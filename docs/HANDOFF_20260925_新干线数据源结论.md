## 3. 代码现状（不要误读为「功能已存在」）

### 3.1 已上线且在发挥作用：T-034 海外显示范围

线上 `2026.09.25.26/.27/.28`，已真机验收：

- 只显示**城际/干线普通铁路**、**高铁（新干线/磁悬浮）**、**长途大巴**
- 排除**地下铁、捷运、subway、市区通勤铁路、市内公交**
- 判据三重（制式 + 线路名/运营方 + 行程尺度），实测依据：
  - 丸ノ内線/東京メトロ = `route_type 1` → 排除
  - **长途大巴与市内公交同为 `route_type 3`**，只能靠尺度区分（≤45 分钟**且**≤40 公里判市内，用 AND 避免误杀 30 分钟/42 公里的干线）
  - 高铁名优先于尺度 ⇒ 东京→品川 12 分钟的新干线仍会显示
- `serviceClass` 驱动图标：高铁=**火箭头** / 干线=**普通火车** / 长途大巴=**大巴**
- 全部候选被排除时用独立错误码 `out_of_scope_service` + 被排除线路清单，文案如实说明「有地铁但海外不显示」
- 真实页面：東京→池袋 → 提示超出范围、`action=trip` **0 次**请求；大分→桜町 高速巴士正常（`coach` 图标）

### 3.2 未启用的预留插槽：T-032 Rome2Rio 长途 provider

- `api/longdistance-proxy.asp` 已上线，**但服务器没有配置 `api/longdistance.config.asp`**
  ⇒ `action=capabilities` 返回 `enabled:false`
- 客户端 `LongDistanceTransitProvider` 每次会话只探测一次**免费能力接口**；
  仅当 12306 明确回 `station_not_found`（=海外/跨境）才走到这一层，
  随后因 `enabled:false` **立即跳过**，**不产生任何第三方调用、不产生费用**
- 实测：海外查询「東京→新大阪」只多发 1 次同源 `capabilities` 探测，`action=search` **0 次**
- **这不是一个功能**。它没有 Key 永远不会启用；UI 也不会显示「全球长途线路源」标签（该标签只在真有结果时出现）
- 接入点已就绪：若将来拿到**长期**数据源，只需在代理里换上游 + 校正 `travelMode` 编码表
  （⚠️ 编码表来自二手资料，未经官方文档确认，用 `?action=selftest` 的真实响应校正）

**待用户/Codex 决定**：按「没有长期数据就没有这个功能」的字面标准，这个休眠插槽是否删除。
默认建议**保留**（零成本、可配置关闭、接入点已测试），但**必须**在文档/对话里明确它是「未启用的预留插槽」而非功能。若要删除，是一次小范围回退 + 一次发布。
