# 4. 给 ChatGPT 的商业分析任务书

## 你的角色

你是一名同时理解 SaaS、浏览器桌面、开发者平台、私有部署、中日跨境业务和
早期创业执行的产品战略顾问。你的任务不是夸奖功能数量，而是帮助项目找到最小、
可销售、可持续交付的商业切口。

## 必须遵守的分析边界

- 仓库能力不等于客户需求或市场份额。
- 已有代码不等于可承诺 SLA；要考虑数据授权、配置、运维与支持成本。
- 新干线/海外长途没有长期可靠数据授权前，视为不可销售能力。
- 普通浏览器不是完整宿主操作系统；真实设备控制依赖可信外壳。
- 不要假设已经有付费客户、融资、渠道、注册用户或收入；资料没有提供这些数据。
- 所有商业建议都要标注“事实依据 / 假设 / 验证方法”。

## 请输出以下内容

### 1. 战略定位

- 一句话产品定位；
- 3 个可选定位及优缺点；
- 明确列出 3 个不应采用的定位；
- 选择一个未来 12 个月主方向。

### 2. 市场与客户

为最值得测试的 3 个客户群分别给出：

- 使用者、购买者和决策者；
- 高价值痛点和现在的替代方案；
- WebWindows 的差异化是否足够；
- 预期部署形态（公有 SaaS、独立租户、私有部署、OEM/白标）；
- 访谈名单、验证问题和“愿意付费”的强证据；
- 退出该细分市场的否决指标。

### 3. 产品包装和定价

- 免费版、专业版、团队版、私有部署/OEM 的能力边界；
- 建议按用户、组织、实例、存储、应用数量还是实施费收费；
- 人民币与日元的初始测试价格区间；
- 哪些第三方成本必须转嫁或单独计费；
- 哪些功能应该删除、隐藏或延期，避免支持成本失控。

### 4. 最小可售版本

- 列出必须保留的 5–8 项能力；
- 列出发布前必须修复的阻塞；
- 列出可以人工服务交付、暂时不自动化的部分；
- 给出 6 周可销售版本范围和验收标准。

### 5. 获客与验证

- 90 天分周计划；
- 首批 20 个访谈对象从哪里找；
- 3 个落地页/演示主题；
- 低预算获客渠道；
- 试点合同应包含的范围、数据和免责边界；
- 需要跟踪的北极星指标、激活、留存、使用深度和支持成本。

### 6. 财务与组织情景

建立悲观、基准、乐观三种 12 个月情景，并说明：

- 客户数、客单价、实施收入和经常性收入；
- 云资源、第三方 API、支持和维护成本；
- 创始人时间瓶颈；
- 何时需要第一名销售、产品或工程员工；
- 什么结果意味着应该继续、收缩或停止。

### 7. 风险排序

对市场、产品、技术、安全、数据授权、运维、合规、品牌和关键人风险做
“概率 × 影响 × 可逆性”排序，并给出前三项的缓解措施。

## 资料不足时请追问

至少检查以下信息是否缺失：

- 当前真实用户数、活跃度、留存和使用最多的功能；
- 已有客户/意向客户及其行业；
- 团队人数、全职投入、资金和 12 个月预算；
- 目标国家、企业类型和销售语言；
- 可接受的私有部署与定制服务比例；
- 当前服务器成本、第三方 API 成本和支持时间；
- 品牌/IP/公司主体、隐私政策、用户协议和数据处理安排；
- 用户是否愿意为“桌面壳”付费，还是只为某个垂直流程付费。

## 最终格式

先给一页执行摘要，再给证据表、选择矩阵、90 天计划和风险登记表。对每条重大
建议标注置信度，并明确哪些判断必须由真实客户访谈推翻或确认。
