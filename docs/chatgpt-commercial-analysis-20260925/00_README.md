## 用途

本目录是给 ChatGPT 或其他商业分析人员使用的自包含资料包。它把当前
WebWindows 的产品范围、已实现能力、技术与运营边界、生产状态、风险及
可讨论的商业化方向整理为可读材料。

本资料包不包含密码、API Key、FTP 凭据、数据库连接串或生产私密配置。

## 建议阅读顺序

1. `01_PRODUCT_AND_MARKET_MAP.md`：产品是什么、有什么、服务谁。
2. `02_TECHNOLOGY_AND_OPERATIONS.md`：技术资产、平台能力和运营方式。
3. `03_CURRENT_STATUS_RISKS_AND_GAPS.md`：哪些已上线、哪些仍受限。
4. `04_COMMERCIAL_ANALYSIS_BRIEF.md`：可直接复制给 ChatGPT 的分析任务。
5. `summary.json`：机器可读的核心事实。

## 使用原则

- “当前事实”来自代码、生产部署清单、功能目录及 OpenCode/Codex 交接记录。
- “商业假设”只是待验证方向，不代表已经有客户、收入、授权或市场份额。
- 分析时应把 WebWindows 视为一个仍在产品化过程中的浏览器桌面平台，而非
  已完成的通用操作系统。
- 涉及交通数据、AI 服务、邮件、地图或第三方 API 的商业方案，必须单独核对
  长期授权、稳定性、成本和地区合规。

## 可直接复制给 ChatGPT 的起始提示词

```text
请阅读我上传的 WebWindows 商业分析资料包全部文件。先区分：
1. 已实现并上线的事实；
2. 已实现但依赖部署配置的能力；
3. 尚未解决的产品/数据/运营限制；
4. 仅供评估的商业假设。

然后以一名懂 SaaS、开发者平台、浏览器桌面、跨境中日业务和早期创业的
产品战略顾问身份，输出：
- 一句话定位与不应采用的定位；
- 最值得优先验证的 3 个付费客户群；
- 每个客户群的痛点、购买者、使用者、替代品、付费理由和验证方法；
- 90 天商业验证计划；
- 免费/付费分层与建议定价区间；
- 获客渠道和中日市场进入顺序；
- 技术债、第三方数据、合规、运维及创始人风险；
- 最小可售版本的明确范围，以及应该暂缓的功能；
- 悲观/基准/乐观三种 12 个月情景。

不要因为项目功能很多就默认它拥有产品市场匹配。每个结论都要注明依据、
假设和需要验证的数据；发现资料不足时列出需要我回答的问题。
```
